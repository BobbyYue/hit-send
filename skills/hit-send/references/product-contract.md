# Hit Send 系统助手契约

## 交互目标

用户在任意工作应用的输入框中写完消息后，按一次全局快捷键。助手读取当前选区或当前输入框，判断后显示建议。用户可以替换、复制或取消，助手绝不代替用户发送。

## 默认体验

- 快捷键：`Control + Option + H`
- 默认模式：原意优先
- 无需改写：显示“这句可以直接发”，原文保持不变
- 需要改写：显示原文和推荐版；只有存在实质策略差异时才显示备选版，并显示最多三条关键原因
- 用户可在版本标签间切换；替换和复制始终作用于当前选中的版本
- 复杂场景或用户明确要求时最多显示三个总版本
- 检测到情绪化、缺少结论/判断、行动不清、时间不清或未闭环时，显示“发送前提醒”，每条同时说明问题和具体改法
- 回车：替换当前文字并返回原应用
- Esc：关闭，不改变原文
- 其他模式：更直接、更柔和、更精简

## 飞书原生入口

- 聊天框“+”菜单：读取用户主动复制的草稿，调用 `rewrite`，结果只复制回剪贴板。
- 消息快捷操作：读取用户主动选中的一至二十条已发送消息，调用 `reply`，可补充“我想表达的要点”。
- 两种入口均在会话侧边栏展示结果，不自动发送消息，不向当前会话写入卡片。
- 飞书公开接口无法读取或覆盖普通聊天输入框中的未发送草稿，因此复制和粘贴是明确的用户确认边界。

## 数据边界

- 仅在用户主动按快捷键时读取当前文字。
- 默认不监听连续输入，不做实时键盘记录。
- 默认不保存历史消息、模型结果或联系人信息。
- 只把待检查文字和必要模式发送给模型。
- 回复场景只发送用户主动选中的消息和主动补充的回复要点。
- 不自动发送，不点击确认，不替用户作业务承诺。
- 捕获或替换失败时，回退到剪贴板；尽量恢复用户原剪贴板内容。

## 失败降级

1. 无辅助功能权限：说明原因并打开系统设置入口。
2. 无法读取当前输入框：提示用户选中文字后再试。
3. 模型不可用：保留原文，显示错误，不做本地臆测改写。
4. 无法写回原应用：把建议放入剪贴板，让用户手动粘贴。
5. 内容适合换渠道：给出一条简短过渡消息，不假装文字能够解决所有问题。

## JSON 结果语义

- `pass`：原文已经可发，`revised_text` 必须与原文完全相同。
- `polish`：只需局部措辞或顺序调整。
- `rewrite`：缺少关键结构，需要用户重点复核。
- `switch_channel`：继续打字的成本或冲突风险更高。

`revised_text` 是推荐版，`recommended_label` 说明它采用的沟通策略。`alternatives` 只承载有实质差异的候选版本：

- `pass` 时必须为空；
- 普通 `polish` / `rewrite` 可以没有备选版；仅在确有策略差异时增加；
- 用户明确要求多个版本时，总版本数最多三个；
- 版本差异应落在结论、证据、行动、时间、协商出口或渠道策略上，不能只是同义改写。

原文没有行动目标时，推荐版和备选版都不得为了“完整”而新增行动、负责人、截止时间、共识或完成状态。动机判断只能改成作者主观感受，或改用原文已经提供的可核验行为，不能转写成另一项未经提供的事实。

`summary` 只描述对方阅读时最重要的判断。`findings` 最多三条，只列会影响理解、行动或关系的问题，每条使用结构化字段：

- `dimension`：问题维度；
- `issue`：原消息中的具体问题；
- `suggestion`：用户下次可以采取的具体改法。

简单确认、事实同步和纯信息问询不机械要求观点或结论；没有实质问题时不显示提醒。

## 运行时

桌面助手直接读取 [runtime-prompt.md](runtime-prompt.md) 作为模型策略，避免每次让 Agent 重新加载完整方法论。修改核心行为时，应同步更新 `SKILL.md` 和该运行时文件。
